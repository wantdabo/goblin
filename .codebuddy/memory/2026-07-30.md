## 投影链路性能优化（Logic → ProjectorSystem → Canvas）

对投影管线做了一轮系统性优化，覆盖 5 个优化点：

### P0-1：IProjectable 索引
- StageCache 新增 `List<IProjectable> projectables` 字段
- AddBehaviorInfo 时若 `is IProjectable` 则加入索引
- Recycle 末尾清理失效条目（`!active || actor==0`）
- Restore 中 behaviorinfodict 重建后全量重建 projectables
- ProjectorSystem.OnEndTick 改为遍历 projectables，跳过非投影类的 is-check
- Standalone 桩 StageCache/StageStub 同步更新

### P0-2：避免 ToArray 二次分配
- ProjectorSystem.packets 类型 `ProjectorPacket[]` → `List<ProjectorPacket>`
- 复用 List，OnEndTick 开头 Clear 而非 new + ToArray
- ProjectionPipeline.Process / Crop.Process 参数改 `IReadOnlyList<ProjectorPacket>`
- GameplayProxy 检查从 `null != ps.packets` 改为 `0 < ps.packets.Count`
- 测试代码 `.Length` → `.Count`

### P1-1：LocalTransport 单 Observer 快路径
- Crop.Process 新增单 Observer 分支
- `mask == p.fieldmask`（无裁剪）时直接共享原 values 引用，跳过 TrimValues
- 多 Observer 路径保持原有 TrimValues 逻辑（避免共享引用数据竞争）

### P1-2：Canvas 字典查找合并
- 原 3 表 `infotoshadow`/`applymap`/`factorymap` 合并为 `infomap`（`Dictionary<Type, ShadowEntry>`）
- ShadowEntry struct 含 shadowtype + factory + apply
- Apply 时字典查找从 5 次降至 3 次（infomap + datas + shadowdict）

### P2-2：TrimValues 零分配（由 P1-1 覆盖）
- 单 Observer + 无裁剪场景共享原 values 引用，零 TrimValues 分配
- 多 Observer 场景仍走 TrimValues（后续可引入 ArrayPool 进一步优化）

### 未实施：P2-1 ProjectorPacket class → struct
- 风险过高：涉及 IGBL 接口契约（Clone 返回 IGBL 装箱）、ObjectCache 池化语义
- 收益不足以抵消改动范围，后续单独评估

### 投影管线第二轮优化（2026-07-30 第四次 session）

### TimeScaleCommand Reset 导致 timescale 变为 1 的 bug 修复（2026-07-30 第四次 session 续）

- **根因**：Herald.cmdqueue 使用 `GBLQueue<Command>`，其 `TryDequeue` 在出队时自动 `Reset()+Set()`，导致 Herald.OnTick 拿到的是已清空的命令（timescale=1）
- 同时 GameplayProxy.OnStep 手动 Reset+Set（冗余）+ Stage.SetCommand 额外 Clone（被 GBLQueue 破坏）
- **修复**（3 文件）：
  1. `Herald.cs`：`GBLQueue<Command>` → 普通 `Queue<Command>`，OnTick 中手动 `Reset()+Set()` 还池
  2. `Stage.cs`：`SetCommand` 移除 Clone（Herald 接管生命周期）
  3. `GameplayProxy.cs`：OnStep 移除 `command.Reset()+ObjectPool.Set(command)`
- 验证：0 错误，89 测试全部通过，3 文件零 Tab
