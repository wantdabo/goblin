## Stage.Restore 崩溃修复

**错误现象**：
- `Stage.Restore()` 抛 `ArgumentException: An item with the same key has already been added. Key: TagInfo`
- 级联 `GameplayView.OnLateTick` 抛 `NullReferenceException`

**根因**：
`Restore()` 中 `Recycle()` 后 `cache.behaviorinfodict` 可能有残留条目（rmvbehaviors/rmvbehaviorinfos 未清理 + 某些 actor 未被 ActorToRecycle 回收）。第一轮循环 `dict.Add(type, info)` 遇到残留 key 直接抛异常，导致第二轮 AddBehavior 循环未执行，`cache.behaviordict` 为空，`seat` 计算属性返回 null。

**修复**（`Stage.cs` Restore 方法）：
1. 开头清理 `rmvbehaviors` 和 `rmvbehaviorinfos`（原代码只清了 `rmvactorset`）
2. `info = snapshot.Clone()` 后防御性 `Reset()` 三个 cache：`behaviorinfodict`、`behaviordict`、`behaviors`
3. `dict.Add(type, info)` 改为 `dict[type] = info`（indexer 容错，避免残留 key 抛异常）

**二次修复**（线程竞争 NRE）：
上面的修复 2（Reset 三个 cache）反而扩大了线程竞争窗口：`OnLateTick`（Godot 主线程）在 Restore 期间读到空 `behaviordict`，`seat` 返回 null，`seat.GetActor()` 抛 NRE。

最终方案：
- 移除 `behaviordict.Reset()` 和 `behaviors.Reset()`（Recycle 后本就为空，无需额外 Reset）
- 保留 `behaviorinfodict` 的 indexer 容错
- `GameplayView.OnLateTick` 加 `seat` 空检查：`var hero = null != seat ? seat.GetActor(...) : 0`

**遗留**：逻辑线程与 Godot 主线程无锁同步，Restore 期间仍有短暂窗口 `behaviordict` 为空（Recycle 清空 → AddBehavior 重建）。空检查是防御措施，根本解决需加线程同步。
